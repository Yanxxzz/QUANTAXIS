# QuantFactra 优化与经营计划

第一阶段服务 **AI 开发者搭建、修改量化研究 Agent**。核心承诺：能快速理解、在本地跑通、替换 AI/平台，并保留研究定义、费用和证据。

本轮有限执行截止为 **2026-10-25 10:00（北京时间，UTC 02:00）**。授权为推分支、建 PR、检查通过后合并到 master；仅准备仓库内容与推广草稿，不向站外发帖。不启动真实模型研究、官网回测、购买、充值或正式池操作。

## P0：先让项目身份与首次运行成立

- 名称、README、包与主命令统一为 QuantFactra；旧入口、历史和上游版权保留。
- 一个无需账户/行情库的首次演示，生成可打开的实际报告、任务账本与回执。
- 平台中立接口覆盖状态、预检、报告和费用；PandaAI 保留原适配。
- 用接口测试验证恢复、身份/单位隔离、未知账单保留与旧平台兼容。

验收：新用户按 README 能运行演示；安装包也能从 checkout 外运行；现有必要回归通过。新官网未真实验证的能力明确标注。

## P1：让开发者知道从哪里改

- 轻量架构地图，说明 Agent、工作流、账本、数据和适配器的职责。
- 回测平台与 AI 接入指南，可运行例子及对应测试。
- 中文主 README 与英文入口，避免把历史过程堆回首次使用说明。
- 贡献指南、问题复现/适配提案模板和 PR 验证要求。

验收：新开发者能找到一个适配器例子、一份协议和一组针对测试；文档链接有效，示例不依赖私有账户。

## P2：做好可信的展示与经营材料

- 原创字标/流程视觉、真实离线输出展示，统一配色与层级。
- 根据相关高 star 项目的可验证做法写[对照分析](open-source-review.md)。
- 准备项目介绍、演示讲解脚本和平台接入招募草稿，明确能力与限制。
- 记录版本变化、迁移方法和后续用户反馈的观察指标。

验收：首屏回答用途、对象、如何启动、怎样修改；推广草稿与实际代码和演示一致。星标增长不作为软件通过证明。

## P3：检查、发布与夜间收尾

- 运行公开源码检查、全套软件回归、包构建/安装检查和离线演示。
- 将本轮改动单独放到基于当前 master 的分支，避免夹带其他未合并研究工作。
- 建立 PR，检查通过后按授权合并；保留失败和修复记录。
- 交付已完成项、仍待核项、PR/验证位置及下一优先级；完成后可提前停止，不为耗时而继续扩搜。

到截止仍有外部阻点时保留真实状态，不把等待中的检查写成通过，不绕过分支规则，不自动延长或安排 heartbeat。

## 本轮之后，按真实反馈推进

1. 收集目标开发者的首次运行卡点和一个实际平台接入需求。
2. 在明确权限与预算下完成第二个真实平台的只读/创建/恢复/报告/费用验证。
3. 根据使用情况决定版本发布与文档站，避免先建设无人使用的营销基础设施。
4. 当接口的真实痛点出现后，再选择一处内部结构或性能问题处理；不做全项目重写。

当前实现与验收状态以关联 PR 和交付记录为准。本计划不授予新的财务研究、对外消息或账户操作权限。
