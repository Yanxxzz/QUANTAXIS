# 条件因子的原生预检

有些因子只在事前定义的股票域中产生分数，例如“过去五日下跌且有完整历史”。默认 `full_universe_strict` 要求大多数输入股票有值，这不适合把域外空值视为正确行为的定义。该默认门槛不变；需要时显式选择 `conditional_domain_research`，仅用于研究，不作为全市场来源、PIT 或入池认证。

新模式使用**完整原始输入面板**及独立的、只由形成时点可用输入生成的资格掩码。掩码不能由候选输出是否有限倒推，也不能使用未来收益选成员。`native_conditional_contract` 绑定窗口、周期、组数、输入文件、布尔资格面板、生成程序和原定义原件的路径及 SHA256；这些原件必须同时列入来源证据。验证器不加载描述符里的程序或模块，只读取和核对原件。掩码是否忠实表达经济定义，仍须独立核验其生成程序和定义。

检查必须同时满足：

- 掩码覆盖完整输入的每个日期／证券键，无重复、缺键、空值或非布尔资格。
- 每个合格点都有有限输出；每个域外点保持空值，不能填零或补中性分数。
- 整个请求窗口都有输入，至少80%的全部样例日期能按无扰动分位数形成所请求的组数。不从第一个有效日期开始删减分母，也不使用只覆盖窗口尾部的样例。
- 修改掩码、生成程序、定义或派发参数，会使原收据失效。派发前重新计算证明，不能手写 `passed=true`。

该模式输出 `research_replay_passed=true`、`passed=false`。收据分别报告资格点覆盖和整个窗口的分组覆盖；全样本中有分数股票占比仍保留作描述，不能冒充生产输入覆盖。原有严格模式、来源转移、投影研究和财务诊断模式互不替换，财务报告期与历史 PIT 门槛保持。

相关实现集中在 `native_preflight.py` 的条件域核验及 `platform.py` 的定义指纹；未新增回测器或执行入口。回归反例在 `tests/test_native_conditional_preflight.py`，覆盖域外漏出、域内缺值、掩码不完整／变更、日期裁剪和派发绑定。
