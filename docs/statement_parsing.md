# 原始财报金额解析

`financial_statements.py` 的金额解析器版本为 2，`statement_layout.py` 的版面解析器版本为 1。CB、GP、WC01、WC02 的原文入口共用金额列核验；WC03 的旧成本附件也重新检查原始列文本，不能用旧缓存绕过拆行检查。输入和输出函数保持兼容，字段契约新增 `amount_parser_version`，恢复过程保存在 `column_parse_evidence` 中。

## 金额列如何确定

1. 完整的两列文本金额可以直接解析。文本中有残留标点、错误千分位分组、粘连数字或不完整小数时，不能只用正则 `findall()` 丢掉无法识别的部分。
2. 中文附注标记按完整语法移除，包括原文中的混合全角与半角括号。裸整数不能仅凭数值较小就认定为附注。
3. 金额主体位于科目上一行时，同样触发版面核验。缺少原件路径时保留待核，不能把另一年度的金额和当前小数尾数当作两列。
4. 版面恢复重新校验原 PDF 和原始文本文件 SHA，核对传入文本、唯一合并报表边界、原文页、科目名称、人民币单位与期间。科目列允许存在额外空白边距列；年度列通过坐标映射到金额单元格。
5. 只能在一个已观察到的金额单元格内连接拆行片段。续页需要同一合并报表边界、实际列头、相同外部表格边界及金额列覆盖关系。当前页存在不明确列头时，不能用前页替代。
6. 母公司报表、营业总成本、不同期间或不同币种不能补入所需字段。横杠、空白、多个候选和损坏 PDF 返回待核状态；合法的小金额、负值与明确零值保留原文数值，再由具体因子检查数值域。

版面核验提供金额证据。披露时间、更正范围、年度/半年报比较、重述检查和因子准入仍由原有研究流程处理，恢复金额不会自动升级完整 PIT 资格。

## 调用与证据

`resolve_statement_columns()` 接收原始全文、字段名称、报表类型、报告期和 provenance；返回金额列、原始片段及解析证据。provenance 提供 `pdf_path`、`text_path`、`pdf_sha256`、`text_sha256`。金额单元格恢复保留原始字符串、坐标、列头、列头页、期间与单位。

`monetary_grid_pair()` 是不依赖 PDF 库的纯表格读取入口。`original_pdf_pair()` 延迟加载 `pdfplumber`，执行原件核验和版面提取。缺少可选库或原件时有明确的待核原因，不会发起网络下载或官网回测。安装研究依赖使用 `requirements-panda-alpha.txt`。

## 缓存与验证

新解析使用新的凭证或修复覆层，记录被替代字段的 SHA。原 PDF、原始提取文本、历史数值与旧结果保留；不能把新代码 SHA 套进旧回执。来源修复不增加策略试验，不触发经济放弃。旧异常输入形成的回测结果需要标记失效，并在新输入通过来源和执行检查后重算。

公开测试含两份虚构中文 PDF，覆盖原件到收入附件的完整链路、金额出现在科目上方、拆行小数、跨页表格、空白列、合并单元格、混合括号附注、错误期间/单位/哈希和损坏原件。真实报告与研究面板留在本机。
