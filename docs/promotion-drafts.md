本文件仅保存草稿；本轮未向站外发布或发送。

## 简介

QuantFactra 是面向 AI 开发者的量化因子研究工作流。它把假设、因子实现、本地核算、平台回测、独立复核与研究证据连起来。你可以接自己的 AI 和回测适配器，同时保留固定定义、原 Run、费用与失败记录。

项目地址：[Yanxxzz/quantfactra](https://github.com/Yanxxzz/quantfactra)。

## 开发社区介绍草稿

我在维护 QuantFactra，希望解决开发量化研究 Agent 时的一个具体问题：模型可以提出和实现很多因子，但换模型、换回测平台或中断恢复之后，往往很难追清同一个实验到底做过什么。

QuantFactra 复用现有本地持仓与费用核算，把平台执行放在适配器后面。PandaAI 保留为内置适配器；新增中立合同支持文字状态、平台自己的预检、免费/预付费回执与规范化报告。其他真实平台仍需具体实现和验收。

首次运行可以完全离线：

```bash
python -m pip install -e .
python -m quantfactra demo --output research_runs/quickstart
```

它会留下一个可打开的 HTML 回执及任务账本，不需要模型 key 或官网账户，也不展示模拟盈利。欢迎对 AI/量化工具有兴趣的开发者试用，反馈哪里难跑、难懂或难接平台。

## 一分钟演示脚本

1. 首屏：一句话说明“为 AI 开发者搭建可追踪的因子研究工作流”。
2. 运行离线 demo，打开真实生成的 HTML 和 summary.json。
3. 展示 create/start/resume/settlement 的同一 Run，并指出零外部调用、来源待核。
4. 打开 DemoAdapter，指出八个接口中使用者需要替换的位置。
5. 展示 AI callable、命令桥接和文件消息入口。
6. 以仓库地址、适配指南和一个明确反馈问题结束：第一次接自己的平台时卡在哪里？
