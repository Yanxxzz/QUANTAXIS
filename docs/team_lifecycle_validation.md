按操作者选择采用当前用户登录后的 Task Scheduler 服务。未安装开机未登录即运行的 SCM 服务，也未保存 Windows 密码。

- 6 项服务回归与原 11 项 runtime 回归通过；本机完整研究测试为 2112 passed、1 skipped。
- 真正注册的 Windows 计划任务完成启动、正常 Stop、重新 Start；强杀专用 PowerShell 启动器、Python 宿主及全部子进程后，由一分钟恢复触发器重新启动，沿原状态完成三轮合成流程，累计 3 次宿主启动。
- 另一个真实 Codex 后台会话完成 1 个限定动作并成功落板，到 action_limit 正常停止；只有 1 次模型尝试、无工具调用，全部所属子进程退出。这验证当前用户后台认证，不替代下节四真实角色的三轮验收。
- 检查发现 Windows 的 RestartOnFailure 设置本身未恢复按需启动的失败任务，因此实际部署使用截止前的分钟恢复触发。故障若发生在进程启动身份回执尚未齐全的窗口，仍按原规则停在 ambiguous_component_launch，不能为追求恢复率而盲目重派。
- 已完成所有进程退出后的磁盘恢复；**尚未实际注销或重启操作者电脑**，真实登录触发的独立验收须保留为待办，不能把进程测试等同于整机重启。

fundamental 将精确来源标识改成说明句，超出合成 grant 的来源集合，lead 在派发前停放该任务。没有为凑执行数而扩大 grant、改写原请求或新增变体。其后两轮两个研究员均独立选择 no_candidate；归档补证没有被解释为新的原生或经济信息。角色包和职责说明已补充精确来源范围及机器标识规则。
