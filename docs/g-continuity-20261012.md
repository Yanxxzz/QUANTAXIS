# G连续更新与夜间新方向

本地G更新链路已经实现，官网生产渠道仍待确认。原`NativeProductionGF.py`保留为已完成历史回测的适配器，没有删除它的日期限制后冒充上线版，也没有向未来复制旧G值。

`panda_alpha/g_continuity.py`提供一个精简、可重复同步的年度事实库；`scripts/update_g_source.py`绑定现有源合同、只增量刷新公告元数据，`AxisProvider.annual_g_asof`供研究框架使用，`ContinuousGF`先计算完整收到价格主体的固定F，再取G/F共同有限样本合成。源码不再保存某段过去日期的逐日SOURCE，也没有固定结束日。新报告到达后更新年度叶子，未解析的新年报、更正、会计/并表问题、同日冲突、刷新失败/过期均保留pending，缺值不填0；迟发现、迟验证不得改写当时已产生的决定。相同财务事实重新搬运不会更新首次发现时间。

G定义保持`((收入本期−成本本期)−(收入同期−成本同期))/平均(期末资产,期初资产)`，同份完整年度报告的合并口径及期间角色必须绑定。年度G不会因半年或季报到来自动变为TTM；后续报告对原年度的重述/比较资产变化须另行核验。期初原印1月1日角色保留，不说成原件印上一年12月31日。G在完整指定财务来源范围内按最新已公开行业版本做平均名次百分位，再与F交集；未使用AR/INV缺项或F缺失来机械改变G的财务资格。最新行业版本遗漏不回退旧版本，同一真实全局文档的已绑定范围分片可合并，来源冲突则pending。

统一操作入口如下。`--execute`是本地源同步；`--refresh-ready`只查已完成源合同的公司公告索引，并用已知年报作阳性对照，不能把服务返回空列表直接说成无新公告。每天需要新鲜的刷新记录；接口读取过期即停止沿用。后续捕获/消费者更新同一清单时，再调用该入口即可加入新事实，无需修改因子公式或旧回测源码。

