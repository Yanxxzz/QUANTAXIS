# 研究文件保留与精简流程

每轮只长期保存研究定义、精简回测结果、继续或淘汰原因。试验账本保存累计次数与人工淘汰决定。有效数据放在共享数据层，由实验引用一次。

## 固定流程

1. **准备数据**：统一行情库；财报保存披露时间、原始提取文本、字段金额及期间、单位、版面证据。已验收字段直接复用，缺失字段定点补充。
2. **登记定义**：固定公式、方向、窗口、调仓周期、分组、费用和比较对象。沿用试验账本中的定义与状态。
3. **执行并保存结论**：保存各组收益、费用、回撤、稳定性、共同样本覆盖及失败原因。保存小型净值曲线。
4. **清理临时产物**：成功写入结论后清除逐股逐日仓位、订单、重复完整快照、测试环境及下载临时文件。新一轮读取同一份数据缓存。

`evaluate` 默认写入精简 `.study.json`。计算与质量评估使用完整结果，存盘时去除逐证券执行数组；需要一次具体收益归因时才添加 `--detailed-output`，完成归因后保留归因结论并清除该临时明细。

## 数据与缓存的区别

- **保留**：行情数据库、交易日历、证券身份、有效财务字段、原始提取文本、来源网址、哈希、有效输入面板、正式池和试验账本。
- **可再取的缓存**：全本公开财报 PDF。文本和字段证据已捕获后，保存原网址与原始 SHA，按需重新取得原件。重新做版面核验时必须真实取得原件并复核 SHA。
- **清除**：同一数据多轮完整 JSON 快照、逐股逐日回测副本、下载残片、进度采样、已完成的安装包与调试符号。

捕获时验收通过与当前本机仍有原 PDF 是两个事实。缓存清理不能伪称原件刚刚通过核验；缺少原件、重新取得的原件哈希变化或字段仍待核时，保留来源待核状态，不能补零、回填新版本或触发经济放弃。

旧完整试验目录不再承担恢复入口。使用当前账本、精简结论、共享数据与来源目录；必要时按原网址和 SHA 定点恢复原件。已失败的旧定义保留失败原因，数据继续用于其它已登记的研究。

## 本机维护

`scripts/audit_project_storage.py` 只读统计大小；`scripts/prune_research_storage.py --plan <清单>` 只预览，添加 `--apply` 才按明确的单文件清单清理。它保护源码、配置、Git、行情库、账本和热记忆；清单生成后发生改动的文件保留。公开 PDF 缓存仅在来源、原 PDF SHA 和原始提取文本 SHA 均符合记录时清除。

夜间维护使用既有清单，完成后保存释放空间、跳过文件及保留数据的报告。研究暂停期间不恢复下载、不回测、不使用官网算力。
