# Panda Alpha：本地优先的因子研究

在 [QUANTAXIS](https://github.com/yutiansut/QUANTAXIS) 上运行的因子研究框架。目标是找到可靠的好因子，同时约束模型额度、官网费用、过拟合与不可交易风险。官网积分是评价信号之一，不单独代替真实目标。

**研究由 Codex 聊天明确启动。** 打开聊天、登录或重启电脑不会启动研究。默认一个主研究员、按需独立审查，共用原任务板和执行网关；不自动修改正式因子池。

## 默认怎样研究

- **一个主研究员。** 默认量价前沿探索，提出独特而可检验的机制；有可用财务输入时可选经营与资本配置方向，不强制两条线同时出提案。
- **本地程序先筛。** 复用取数、预检和回测内核。固定定义明确弱时停放；本地数据确实难以取得时，附证据转必要官网验证。
- **入围后独立审查。** Skeptic 一次审冻结设计与本地证据，结果出来再独立复核；不让作者自审，不把设计批准当作来源或入池通过。
- **程序调度与结案。** 不再固定调用 Lead 计划、冻结和复述结论；宿主机械落实独立决定，已有跨线异议仍须明确处置。

新模板仍用 `gpt-6.1-sol`，主研究员 `high`、审查 `xhigh`，最多 **16次真实模型尝试（含重试）**，每工作最多2次；单次提示180KB，按候选分离会话，只附相关上下文。完整候选通常3个模型动作，本地停放只需提案；这不是实测额度节省比例，也不保证统计独立。见[精简流程与额度控制](docs/lean_research.md)。

[原件审视与有限研究方案](docs/research_depth_audit.md)复核三类历史反例，只补新lean路径缺少正面语义证据也能进入官网替代的遗漏。下一步只准备一个跨股票信息传导机制，先区分自身反转和共同风险，再看同样本成本后表现；未启动、未读取新候选收益。官网余32点/6槽与worker16次均为后续上限，需新有限授权和绝对截止，研究继续停止。

旧四角色部署及 max/ultra 配置保持原样；缺少 `workflow` 的旧 spec 按原协议恢复，不原地改绑或复活终态。复杂问题可明确选择旧流程。新增证据仍返回同一任务，固定待核编号和证据替代关系保留。

## 本地初筛，必要时官网验证

复用既有 `study.prepare_study/evaluate_study`、实际持仓账本与质量评估，不另造一套回测器。先冻结代码、方向、窗口、分组、交易日历和失败条件，再计算信号与收益。

本地筛选检查次日开盘成交、30/50bp 单边成本、分组与同支持集市场对照。实际数据难以取得时保存具体缺口，按授权转官网；不能用零收益填补缺行情，也不能事后删除难以交易的股票。代码错误、语义不匹配、损坏输入或证据哈希不符会阻断。

原生 DSL 与本地同名算子不自动等价。已核实的公开 SDK 存在排秩、缺失和滚动语义差异；明确 Python 实现先验证逐证券完整日历、数值退化、实际公开类入口及分析日期消费者。日线可输出严格逐键等价的 `YYYYMMDD`，不能改变日期、证券、顺序或数值。日期表示详见[原生日线日期](docs/native_date_wire.md)。公开源码回放不认证生产部署；本夜新 MAX20 的一次真实全链成功只认证该次运行的交付能力，不回溯证明旧 Run 的根因。

官网报告经过结构验收，真实 IC 序列和分组统计交给 Skeptic，再由宿主按独立决定写入科学记忆。**运行结算、报告交付、来源资格和经济有效性分别判断**：技术失败不当作经济零值；汇总 Sharpe 不冒充真实净成本或现池增量。已有 Run 只按原 ID 恢复，不重复创建。

## 怎样判断值得入池

优秀研究候选和正式入池分开。当前有限研究在读取结果前冻结：主窗方向对齐 RankIC 均值至少 0.03、预选持有组 Sharpe 至少 1.0、年化超额为正；同代码确认窗至少 0.02／0.8／正超额。均要求至少 24 个 IC 观察、覆盖 120 个实际交易日。不得改方向、挑最好分组或用累计 RankIC 替代周期均值；已暴露窗口不称独立封存样本。

前瞻正式准入采用 [v3 政策](config/pool-admission.v3.json)：最低观察期从 200 降至 60 个调仓周期、正收益折数从 5 降至 3；高费档、换手、规模与相关性压力不足时进入明确的人工权衡。来源/PIT、标准成本质量、真实池共同执行及增量证据仍需满足。旧 v1/v2 判断不改写，细则见[入池规则](docs/pool_admission.md)。

不以单个指标或加权总分代替研究目标。保留失败、竞争解释、全部已读窗口和累计尝试；机制被反证时撤回对应主张，即使某项摘要漂亮。模型调用只推进新信息和决策，官网运行必须有可改变判断的信息价值。

## 启动、停止与恢复

推荐 Python 3.11；研究层无需部署上游 Web、交易或 Rust 服务。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-panda-alpha.txt
.\.venv\Scripts\python.exe -m panda_alpha.team --help
.\.venv\Scripts\python.exe -m panda_alpha.team host-demo --output research_runs/team_demo
```

`host-demo` 使用合成角色及隔离账本，覆盖三轮协作和中断恢复，不调用真实模型或官网；输出目录须尚不存在。

真实研究在聊天说明目标、资金范围、动作/运行上限及绝对截止。Codex 先核对原状态，再用 `host-init`、`service-prepare` 绑定有限会话。统一控制已有部署：

```powershell
python -m panda_alpha.team host-control --deployment DEPLOYMENT.json --action status
python -m panda_alpha.team host-control --deployment DEPLOYMENT.json --action start
python -m panda_alpha.team host-control --deployment DEPLOYMENT.json --action stop
```

官网部署必须在准备时显式绑定执行配置，并在启动时带 `--execute`；标志本身不激活资金授权。默认离线，无 Windows 自启。进程查询使用与启动相同的可见环境；沙箱看不到外部宿主不能当作进程已死。

超时、断线与组件退出沿原 `work_id`、模型会话和剩余次数有限恢复；已完成或过期会话不复活。新有限修复会话仍计入同一总体边界。未知创建状态进入对账，不猜测并重发。`stop` 停止本机派发和轮询，**不代表官网取消或退款**。操作细则见[聊天启动](docs/chat_start.md)和[无人值守宿主](docs/unattended_host.md)。

## 代码与状态放在哪里

维护核心：

- `panda_alpha/team/`：请求协议、任务板、角色调度、宿主、证据验收和本地路由。
- `panda_alpha/platform.py`、`research_budget.py`：官网网关、共享预算、预留、原 Run 恢复及结算。
- `panda_alpha/registry.py`、`memory.py`：定义登记、科学事实与历史约束。
- `panda_alpha/study.py`、`execution.py`、`admission.py`：本地核算、执行及准入。
- `.codex/agents/`、`config/`：角色职责与配置模板；`tests/`：离线回归。

实验账本与科学登记是权威状态，JSON 工作包是带哈希的证据与可恢复视图。团队不另建模拟余额；预留与真实消费共同占额，扩额保留旧用量并追加审计。可逆上下文去重只压缩完全重复内容，保留还原能力；字节下降不等于 token 或质量同比改善。

上游代码与可复用研究组件保持路径；一次候选不自动成为常驻框架。可再生缓存和校验后的重复副本可清理，冻结数据、代码、原回复及真实失败保留。详见[架构](docs/architecture.md)、[预算](docs/official_compute.md)和[证据存储](docs/research_storage.md)。
